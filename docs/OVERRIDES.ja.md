# Overrides：Inspector での編集を、そのまま Mod にする

[English](OVERRIDES.md)

> **Overrides 0.1.0 を作りました**（実験的）。ゲームで確かめたこと：ファイルを読む、シーンの読み込み時と竜が来たときに値を当てる、Mods 画面に並べる・オフにする、競合。Inspector の **Export as overrides**（History の画面）も作りました。調査は終わりました（[作る前の調査](#作る前の調査)）。調査で変わったところには **変更** と書いてあります。

Inspector を使えば、誰でも動いているゲームの値を変えて、すぐに結果を見られます。ただし、ゲームを閉じればすべて消えます（[INSPECTOR.ja.md](INSPECTOR.ja.md) では、保存は「のちの overrides の設計」に回しています）。これがその設計です。**History にたまった編集をファイルにし、そのファイルをコード不要の Mod にします。** C# を書いたことのない人でも、ドラゴンを重くしたり、ライトを暖かくしたり、スポンジをゆっくりにしたりして、友だちに渡せます。

Toolsmith の考え方を、そのまま 1 つの機能にしたものです。フレームワークは道具を作り、何を作るかは使う人が決めます。

## 全体の流れ

```
Inspector（開発者ツールがオンのとき）   Overrides ライブラリ（常に。遊ぶ人向け）
  値を編集  ->  History                  plugins/<Mod>/overrides/*.json
  [Export as overrides]  ----------->    起動時に読む
                                         シーンが読み込まれたら適用
                                         オフにしたら元に戻す
```

## 2 つの部分、2 つの置き場所

- **書き出し**は Inspector の仕事です。何を変えたか、変える前と後を、History がすでに知っています。書き出しは History のボタン 1 つと、Tool window の数行の UI です。
- **適用**は新しい小さなライブラリ **Overrides** の仕事で、Inspector には置きません。遊ぶ人は開発者ツールなしで使いますし、Mod はリリースから Inspector を外すことがあるからです。Assets ライブラリにも置きません（INSPECTOR.md では最初そう考えていました）。Assets はゲームのファイルの代わりになるファイルを扱います。こちらはシーンの中のオブジェクトの値を扱います。1 つのライブラリには 1 つの仕事です。

## override とは

ファイルの 1 行で、どこの・何を・どの値に、を書きます。値は Inspector の行と同じ書き方にするので、手で読んで直せます。

```json
{
  "format": 1,
  "overrides": [
    { "scene": "Wash", "path": "Dragon/Body", "component": "Rigidbody", "member": "mass", "value": "2.5" },
    { "scene": "Wash", "path": "Lights/Key", "component": "Light", "member": "color", "value": "#FFD9A8FF" },
    { "scene": "Wash", "path": "Dragon/Body", "material": "DragonSkin", "property": "_Smoothness", "value": "0.8" }
  ]
}
```

- **どこの**：シーン、オブジェクトのパス（Console の `inspect` と同じ書き方）、型名で指定するコンポーネント。同じ型のコンポーネントが 2 つあるときは `"index"` でどれかを示します。
- **何を**：public なフィールドかプロパティ。マテリアルのプロパティは、それを表示している Renderer を通して指定します。private なメンバーは `"private": true` のときだけ扱い、Mods 画面にそう出します。
- **値**：テキストです。行と同じ `InspectorModel.Parse` で読むので、数値、真偽値、文字列、enum、ベクトル、色、Rect、Quaternion が使えます。**オブジェクトの参照（テクスチャ、メッシュ、ほかのオブジェクト）は扱いません。** アセットの差し替えは Assets ライブラリの仕事ですし、参照はそもそも値として書けません。
- **最初の版には入れないもの**：メッシュの頂点の編集（これは値ではなくデータなので、Asset tool のエクスポートとインポートで扱います）、リストの要素、コンポーネントの追加や削除。

## 遊ぶ人が受け取る Mod

書き出すと、DLL のない、それだけで完結した Mod のフォルダーができます。

```
BepInEx/plugins/Heavier Dragon/
  mod.json              名前、作者、説明、バージョン
  overrides/main.json
```

Overrides ライブラリは `plugins/*/overrides/` を探し、`mod.json` を読んで、フォルダーごとに 1 つの Mod としてフレームワークに登録します（`ModInfo`）。そのため Mods 画面に名前と作者つきで出て、ほかの Mod と同じようにそこでオフにできます。コンパイルするものも、実行するものもありません。

## いつ適用し、どう戻すか

- シーンが読み込まれたとき（`GameEvents.OnSceneLoaded`）と、その少しあとにもう一度。読み込み直後にゲームが作るオブジェクトのためです。
- 最初に書き込む前に、ゲームが持っていた値を覚えておきます。Mod をオフにすると、テクスチャの差し替えと同じように、すべての値を元に戻します。
- 対象が見つからなくてもエラーにはしません。Mods 画面に「20 件中 3 件の override は対象が見つかりません」と出し、パスはログに書きます。ゲームのアップデートでオブジェクトの名前が変わっても、失うのはその override 1 つだけで、ゲームは止まりません。
- ゲームのスクリプトが、同じ値を毎フレーム書き直すことがあります。最初の版はそれと争いません。どのくらい起きるのか、「適用し続ける」が必要になることがあるのかは、調査で確かめます。

## Mod どうしで

すべての Mod が安全に共存すること、が物差しです。

- 2 つの Mod が同じオブジェクトの同じメンバーを変えるときは、読み込み順であとのほうが勝ちます。そして Mods 画面には**両方の**名前を出します（予定している Mod ごとの注記を使います）。自分の編集が効かない理由が分からない、ということをなくします。
- override は何も消さず、メソッドを呼ばず、コードを読み込みません。

## コンテンツポリシー

override のファイルが持つのは、人が手で変えた値と、オブジェクトを見つけるのに必要な名前（パス、コンポーネント名、メンバー名）だけです。これは[コンテンツポリシー](CONTENT_POLICY.ja.md)に合っています。手で作ったもの・変えたものは OK で、ゲームのデータをそのまま写したものは NG です。書き出すのは History が変更として記録したものだけで、オブジェクトの値をまるごと書き出すことはしません。

## 作る前の調査

2026-09-19 に行いました。調査用の小さな Mod（公開しません）で、次のことをしました。
- シーンを読み込むたびに、1 秒後・5 秒後・20 秒後の全オブジェクトのパスを書き出す。
- 一番上のオブジェクトが現れたり消えたりする時刻を測る。
- 竜のコンポーネント、ライト、Rigidbody の値を 5 秒で 20 回読む。
- 動かなかった値を 0.1% だけ変え、1 秒後に読み戻す（そのあと元に戻す）。
- 値を Inspector の `Format` と `Parse` で往復させる。

遊んだ順は、タイトル、PlayGame、タイトル、PlayGame です（Direct3D 12、2026-09-14 のゲーム）。あわせて、Mods 画面と History のフレームワークのコードを読みました。

1. **パスは変わらない。** タイトルのシーンは 2 回とも同じ 1,360 のパス、PlayGame も同じ 1,675 のパスでした（`TemporaryVFX` や `ParticleSpline (Clone)` のような、すぐ消える演出を除く）。
   - パスはほとんど重なりません。タイトルでは 0、PlayGame では 9 のパス（66 オブジェクト。ほとんどが `DickApprox(Clone)` の中、少しが `map_prefab`）が重なりました。重なったときの `"index"` は要りますが、まれです。
   - まだ確かめていないのは、ゲームのアップデートをまたいだときです。テクスチャの調査ではビルドどうしを比べているので、次のアップデートのときにパスも同じように比べます。
2. **あとから作られるオブジェクト。** 竜（ここでは `DragonAlexander_1 (Clone)`、295 オブジェクト）と `DickApprox(Clone)` は、PlayGame の最初のフレームからあります。なので、最初の竜には、シーンの読み込みともう一度の適用で届きます。
   - ただし、竜はレベルごとに別の名前で、そのレベルが始まるとき、つまりシーンの読み込みよりずっとあとに作られます。
   - **変更**：シーンの読み込みのほかに、新しい一番上のオブジェクトを見張ります（0.5 秒ごとに、シーンの一番上の一覧を軽く確かめる）。現れたら、パスがそのオブジェクトで始まる override を当てます。これで `DragonRyanA (Clone)/...` の override は、その竜が来るたびに効きます。
3. **ゲームが書き直す値は少ない。**
   - 読んだ 972 のメンバーのうち、自分で変わったのは 17 だけで、すべて動きでした（Animator のルートや体の位置と速さ、Rigidbody の速さ・位置・重心、VFX の粒の数）。どれも override で変えるものではありません。
   - 少し変えた 58 の値のうち、57 はそのまま残りました。ゲームに戻されたのは 1 つ（竜の `AudioSource.volume`。スクリプトが設定しています）です。
   - ライト（32 の値）と竜のスクリプトは、変更をすべて保ちました。
   - 例外は、Inspector がすでに注意書きしている骨です。Animator が毎フレーム書き込みます。
4. **ゲームのスクリプトは、設定を private なフィールドに持っている。**
   - 竜のゲームのスクリプトの public なフィールドは、全部で 38 しかありません。遊ぶ人が変えたくなるもの（速さ、強さ、しきい値）は、ほとんど private な `[SerializeField]` のフィールドにあります。Inspector では **Show private** で見えます。
   - **変更**：`"private": true` は例外ではなく、ゲームのスクリプトを変えるときの普通のやり方になります。Mods 画面には、今までどおりそれを使う Mod だと出します。
5. **DLL のない Mod。**
   - Mods 画面の一覧は、BepInEx が読み込んだプラグイン、フォルダーにあるプラグインの DLL、プリローダーのパッチャーから作られます。Mod をオフにすると、次の起動時に DLL の名前を変えます。
   - データだけの Mod には、一覧の 4 つ目の入り口が要ります（Overrides ライブラリが見つけたフォルダーを登録する）。オフの仕組みも、同じやり方で `mod.json` を `mod.json.disabled` に変えることにします。次の起動からオフになり、ライブラリはそれを読みません。
   - アンインストールは、ほかの Mod のフォルダーと同じです。
6. **往復。**
   - Inspector の `Format` と `Parse` で往復させると、整数、真偽値、enum、Vector2、Vector4、Color32 はぴったり戻りました。
   - float（149 のうち 16）、Vector3（26 のうち 18）、Quaternion（8 のうち 6）、Color（8 のうち 8）は、近いけれど同じにはなりませんでした。`Format` が小数点以下 3 桁で、回転をオイラー角で出すからです。
   - 丸めずに書くと（float は `R`、回転は x, y, z, w）、すべてぴったり戻りました。
   - **変更**：ファイルには、行に出す文字ではなく、ライブラリ自身の丸めない形式（`Serialize` / `Deserialize`）で書きます。人が手で書いたものは、今までどおり `Parse` で読みます。
7. **History。**
   - いまの記録にあるのは、人が読むラベルと、インスタンス ID でできたキーだけです。キーはゲームを再起動すると使えなくなります。
   - **変更**：Inspector が記録を作るときに、シーン、パス、コンポーネントの型と同じ型の中での番号、メンバー、private かどうかも残すようにします。

ついでに分かったこと：PlayGame を読み込むたびに、およそ 24 個の `JigglePhysicsDummyTransform` が DontDestroyOnLoad に残り、消えません（ゲームの揺れの物理の小さな漏れで、フレームワークのものではありません）。

## 作業の順番

1. 調査ノート（上）：済み。
2. Overrides ライブラリ：ファイルを読む、DLL のない Mod を登録する、適用する、元に戻す、報告する。
3. Inspector：各編集がどこで行われたか（シーン、パス、コンポーネント、メンバー）を記録します。今の History が持っているのはラベルとインスタンス ID だけです。そのうえで History の画面に **Export as overrides** をつけます。
4. ドキュメント：Mod を作ったことのない人向けのページ。「Inspector で変えて、Export を押して、フォルダーを送る」。
