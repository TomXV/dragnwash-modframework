# 操作の登録簿、MCP、ノードグラフ：計画

[English](API_PLAN.md)

> **第 1 段階を作りました**（実験的）。中核の登録簿、Console の `op`、中核・Tool window・Inspector・Flags and saves の読む操作です。Assets、Dialogue、Text はこのあと。そのほかの段階はまだ計画で、最初は `experimental/api-mcp` ブランチに書きました。各段階は、コードの前にそれぞれ設計と調査をします。このページは、どんな段階があり、どの順番で進め、何がそれらをつなぐかを書いたものです。

3 つの願いを、1 つの土台で叶えます。

1. **すべてのライブラリを API に**：各ライブラリにできることを、C# からだけでなく、名前と素直な引数で呼べるようにします。
2. **MCP**：同じものを、AI のクライアント（Claude など）が Model Context Protocol で理解して使えるようにします。
3. **ノードグラフ**：今あるコードをノードとして眺め、新しい動きをブロックやノードで組み立てます。C# は書きません。

3 つとも、1 つのものの別の見え方です。それが、各ライブラリが自分にできることを載せる**操作の登録簿**です。

```
        各ライブラリが自分の操作を登録（持ち主は各ライブラリ）
                                   │
       ┌───────────────────┬───────┴───────────┬────────────────────┐
  Console コマンド       MCP のツール        ノードグラフのブロック   C#（今まで通り）
  （人が打つ）           （AI クライアント）   （人が並べる）
```

Core が持つのは窓口だけで、その奥は各ライブラリのものです。フレームワーク全体と同じ考え方で、Core はすべてを抱えません。

## 決めたこと（2026-09-19）

- **MCP は読むだけから始めます。** AI クライアントは見ること（オブジェクト、値、ログ、Mod）はできますが、何も変えられません。書き換えは、あとで改めてそれだけを決めます。
- **ノードエディタはゲームの外に置きます。** ゲームがこの PC の中だけで出すブラウザのページで、ゲーム側はグラフを実行するだけです。F1 の窓（IMGUI）にノードエディタを描くのは重く、Direct3D 12 の文字の制限も受けます。
- **組み立ては、登録された操作だけで認めます。** ロードマップには「スクリプト言語は予定していない」とありました。これを「*自由な*スクリプト（任意のメソッド、リフレクション）はしない。ライブラリが登録した操作だけを呼ぶグラフは作る」に改めます。グラフにできることは操作が許すことそのもので、どの操作を使うかは Mods 画面に出します。
- **順番**：登録簿 → MCP → コードをノードで眺める → 組み立て。

## 第 0 段階：棚卸し

今の各ライブラリが提供しているもの（2026-09-19）：

| ライブラリ | 公開している型 | Console |
|---|---|---|
| Core | ModFramework、ModInfo、GameEvents、GameHooks、GameInfo、GameOptions、DeveloperTools、ModReload、NetworkWatch、Services ほか（18） | `mods`、`scene` |
| Tool window | ToolWindow、ConsoleLog、ConsoleCommands ほか（6） | `help`、`log`、`clear` |
| Assets | GameAssets、AssetCatalog、AssetReplacements、GameFonts ほか（9） | `assets` |
| Dialogue | GameDialogue、LineKey、LineResolver ほか（7） | |
| Text | GameText、TextContext | |
| Saves | GameSaves、GameFlags、SaveSnapshot、FlagInfo | |
| Inspector | Inspector（1。ほかは内部） | `inspect` |

棚卸しの仕上げは第 1 段階の設計で行います。公開しているメンバーとコマンドの 1 つずつに、操作にするかどうかと、その名前を書きます。

## 第 1 段階：操作の登録簿（Core）

Core に小さな登録簿を置きます。`Services` の隣です（`Services` は残します。`Services` は Mod どうしの型つきの C# で、操作は C# の外から呼ぶ人のために名前と説明をつけたものです）。

- **操作**には、名前（`ライブラリ.名詞.動詞`、たとえば `inspector.member.get`）、1 行の説明、引数（名前、型、必須かどうか、説明）、返すもの、そして**種類**があります。種類は、*read*（何も変えない）か *write* です。
- **型**は JSON で運べるものだけです。文字列、数値、真偽値、enum、それらのリストとオブジェクト。ベクトルや色は文字列で運び、Inspector の行と同じように読みます。
- **メインスレッド**：Unity のオブジェクトはメインスレッドでしか触れません。誰が呼んでも、呼び出しは列に並べてメインスレッドで実行します。
- **持ち主**：ライブラリの GUID で登録し、ライブラリと一緒に外れます（`ModReload` が、Mod の登録したほかのものに対してすでにしている通りです）。
- **呼び出しはすべてログに残します。** 誰が呼んだか（Console、MCP、グラフ）を書きます。書き換えは、Inspector の History がある場合はそこに入り、元に戻せます。
- **Console**：`op <名前> key=value …` でどの操作でも実行でき、補完もします。今あるコマンドはそのまま使え、あとで薄い包みになります。

最初の操作（読むものから）：

| ライブラリ | 操作 |
|---|---|
| Core | `mods.list`、`mods.network`、`game.info`、`scene.list` |
| Tool window | `log.read` |
| Inspector | `objects.find`、`objects.children`、`components.list`、`member.get`、`selection.get`（のちに書き換えの `member.set`） |
| Assets | `textures.list`、`materials.list`、`meshes.list`、`replacements.list` |
| Dialogue | `dialogue.current`、`lines.find` |
| Text | `text.lookup`、`text.language` |
| Saves | `saves.list`、`flags.list`、`flags.get` |

Mod も同じやり方で自分の操作を登録できます。Drag'n Wash Localization なら `loc.line.get` や `loc.coverage` を出せます。

## 第 2 段階：ローカルの窓口と MCP

新しい、入れなくてもよいライブラリ **Bridge** を作ります。独立したプラグインなので、Mod のリリースから外せます。

- **この PC の中だけ。** 待ち受けは `127.0.0.1` のみ（ポートは設定）です。セッションごとにトークンを作り、この利用者だけが読めるファイルに書きます。ほかのアドレスからの接続は断ります。
- **既定はオフ**で、開発者ツールがオンのときだけ動きます。`ModInfo.Network` で自分を申告します（自分の PC の中でも接続は接続で、[NETWORK.ja.md](NETWORK.ja.md) の考え方どおり遊ぶ人に見えるようにします）。Mods 画面には *Bridge 待ち受け中* と *AI クライアント接続中* を出し、切断ボタンもつけます。
- **MCP**：Bridge は Streamable HTTP で MCP を話します。`tools/list` は登録簿から作り、**read の操作だけ**を出します。`tools/call` はメインスレッドで 1 つ実行して JSON を返します。説明は登録簿から取るので、AI クライアントは、人が `help` を読むのと同じように理解します。
- ローカルのプログラムを起動する形の MCP クライアントしか使えない人向けの、小さな stdio の仲立ちは、必要とする人が出てきたら作ります。
- **制限**：結果の大きさに上限、呼び出しの回数に上限。操作が出すもの以外に、ファイルへの読み書きはしません。
- 同じ Bridge が、のちにノードエディタのページと、その素直な JSON の API も出します（第 3・第 4 段階）。

## 第 3 段階：コードをノードで眺める（読むだけ）

Inspector の Code 表示は、すでに Mono.Cecil でメソッドの IL を読み、型についている Harmony のパッチと UnityEvent のリスナーを知っています。

- 操作 `code.graph` が、メソッドや型をグラフとして返します。メソッドのブロックと分岐、呼び出すメソッド、読み書きするフィールド、ついている Harmony のパッチ（とその持ち主）、どのイベントからそこへ来るか、です。
- エディタのページがそれをノードとして描き、ノードを開くと次のメソッドへ進めます。
- **構造であってソースではありません。** C# への逆コンパイルはしません（それは dnSpy や ILSpy の仕事のままです）。ゲームのコードを、ファイルに書いたり、この PC の中のページ以外に送ったりもしません。[コンテンツポリシー](CONTENT_POLICY.ja.md)を参照してください。

## 第 4 段階：ブロックとノードで組み立てる

- **グラフ**はデータです。イベント（シーンが読み込まれた、キーが押された、会話の行が出た）、操作（read と write）、少しの流れ（もし、待つ、回数に上限のある繰り返し）、そして値です。
- **ブロック**（Scratch のような）と**ノード**は、同じグラフのファイルを編集する 2 つのやり方です。
- グラフは [Overrides](OVERRIDES.ja.md) と同じ形で配ります。`mod.json` と `graphs/*.json` のフォルダーで、DLL はなく、Mods 画面に出てオフにできます。Overrides とグラフは、その読み込み処理を共有します。
- 小さな **Graphs** ライブラリがグラフを実行します。登録された操作だけを使い、1 フレームごとに時間の上限を設けます。3 回続けて失敗したグラフは（`GameEvents` のハンドラーと同じく）オフにします。Mods 画面には各グラフが使う操作を出すので、グラフに*何ができるか*を、動く前に見られます。

## 順番と物差し

| 段階 | 内容 | 場所 |
|---|---|---|
| 0 | 棚卸し | このページ、次に第 1 段階の設計 |
| 1 | 操作の登録簿、Console の `op`、最初の read の操作 | Core、各ライブラリ |
| 2 | Bridge と MCP（読むだけ） | 新しい Bridge ライブラリ |
| 3 | コードをノードで眺める、エディタのページ | Inspector、Bridge |
| 4 | グラフ：ブロックとノード、DLL のない Mod | 新しい Graphs ライブラリ（Overrides と共有） |

物差しは変わりません。すべての Mod が安全に共存すること。どの部分も、ほかの人が続きを担えるくらい小さいこと。Mod（や AI クライアント、グラフ）に何ができるかを、遊ぶ人に見せること。
