# オブジェクトエクスプローラー（設計）

[English](OBJECT_EXPLORER.md)

> **作りました。実験的で、まだ main には入れていません。** 2026-09-18 に `experimental/object-explorer` ブランチで設計し、2026-09-20 に今の Inspector に合わせて見直して、`experimental/object-explorer-build` で作りました（[作る順番](#作る順番)の 6 段階すべて）。確かめたのはゲームの外だけです。main に入れる前に、ゲームの中での確認が要ります。**Inspector** ライブラリ（[Inspector（Wiki）](https://github.com/TomXV/dragnwash-modframework/wiki/Inspector-ja)）の一部なので、これも実験的な機能で、開発者ツールの機能です（[ほかの Mod と仲良くするために（Wiki）](https://github.com/TomXV/dragnwash-modframework/wiki/Playing-well-with-others-ja)）。

Inspector が見せるのは **シーンの中にあるもの**、つまり Hierarchy、オブジェクト、そのコンポーネントです。ゲームが読み込んでいるものは、それだけではありません。テクスチャ、マテリアル、メッシュ、シェーダー、音、アニメーション、フォント、そして ScriptableObject に入ったゲーム独自のデータがあります。多くはシーンのどこかのオブジェクトにぶら下がっていますが、まとめて見る場所がありません。オブジェクトエクスプローラーは、その場所です。読み込まれているものすべてを種類別に並べます。Unity エディタの Project ウィンドウのようなものですが、中身は動いているゲームが読み込んでいるものです。

## 何のためで、何ではないか

- **調べる。** ゲームがどのテクスチャや音を読み込んでいるか、ゲームのデータを持つ ScriptableObject に何が入っているか、マテリアルがどのシェーダーを使っているか、そして**それぞれがどこで使われているか**。
- **試す。** Inspector の行と同じ編集を、これらのオブジェクトにもできます。保存はしません。
- **書き出しはしません。** アセットをファイルに書き出すのはアセットツール（[Assets（Wiki）](https://github.com/TomXV/dragnwash-modframework/wiki/Assets-ja)）の 3 番目の段階で、そちらに残します。
- **差し替えはしません。** プレイヤーに届くマテリアルの差し替えは Assets ライブラリの仕事で、テクスチャの差し替えの隣に、後で別に設計します。
- オブジェクトの作成・複製・削除、アセットバンドルの読み込み、音の再生は、最初の版には入れません。

## タブ

Inspector のツールバーの先頭に **Scene | Objects** の切り替えがあります。**Scene** は今までのタブのままです。**Objects** では、左の欄がエクスプローラーになります。右側は今までの中身の欄のままなので、その欄でできること（行、編集、Reset、History、Code）がここでも使えます。中身の欄の代わりに出る表示（History、Rigidbodies の一覧、Scenes and levels）も同じです。

- Objects では、ツールバーの **Tree** ボタンが **List** になり、エクスプローラーを出したり隠したりします（**T** キーも同じ）。**Parent** は出しません。Pick、Edit、View、History、Refresh はそのままで、**Refresh** は読み込まれているオブジェクトを並べ直します。
- 検索の文字と選択は、表示ごとに別に持ちます。Scene に戻ると、Scene で選んでいたものがそのまま選ばれています。
- Scene で選択のパスを出している場所に、Objects では状態の行を出します。並べたオブジェクトの数、かかった時間、お知らせです。
- どの欄にもキーボードが入っていないとき、**キーで左の欄の一覧を移動できます**（Scene のツリーと検索結果、Objects のフォルダーとオブジェクト、どちらでも）。上下で 1 行、PageUp と PageDown で 1 画面、Home と End で先頭と末尾です。右キーはフォルダー（や子を持つノード）を開き、すでに開いていれば中の最初の行へ移ります。左キーは閉じ、閉じるものがない行では、その行が入っているフォルダー（や親）へ上がります。オブジェクトに移ると、それが選ばれるので、右側もキーについてきます。狭い窓では一覧が出たままです（クリックのときは今までどおりページが変わります）。一覧は、その行が見えるのに必要な分だけスクロールするので、1 行ずつ動かしても画面が飛びません。Objects ではフォルダーの行にもキーが止まります。フォルダーは選択ではないので、キーがいる行は、選ばれている行と同じように塗って示します。 Steam Deck やゲームパッドでは、**十字キー**がこのキーの代わりになります。ウィンドウが十字キーを本物の矢印キーとして送るので、1 行ずつの移動も開閉も、押しっぱなしのリピートも同じに働き、キーボードがなくても一覧をたどれます。スクロールは今までどおりスティックです。

### 左の欄：種類とオブジェクト

種類ごとのフォルダーを、件数つきで並べます。

| フォルダー | 入るもの |
|---|---|
| Textures | `Texture2D`、`RenderTexture`、`Cubemap` などの `Texture` |
| Sprites | `Sprite` |
| Materials | `Material` |
| Shaders | `Shader` |
| Meshes | `Mesh` |
| Audio | `AudioClip` |
| Animation | `AnimationClip`、`RuntimeAnimatorController`（オーバーライドコントローラーも） |
| Fonts | `Font`、`TMP_FontAsset` |
| Data | `ScriptableObject`。型ごとのサブフォルダーに分け、ゲーム独自の型を先にします（ゲームのアセンブリかどうかはコードグラフと同じ決め方） |
| Objects outside the scenes | 読み込まれたどのシーンにも属さない `GameObject` すべて（ゲームが読み込んだままにしているプレハブや雛形）。パスで並べます |
| Other | それ以外。型ごとのサブフォルダーに分けます |

- コンポーネントは並べません。シーンのものは Scene に、シーン外の GameObject のものはその GameObject の下にあります。
- フォルダーを開くと、オブジェクトが並びます。名前と、種類ごとの短い情報をひとつ出します（テクスチャならサイズと形式、メッシュなら頂点数とサブメッシュ数、クリップなら長さ、マテリアルならシェーダー、GameObject ならコンポーネントと子の数）。短い情報は、その行を初めて描くときに読んで、覚えておきます。
- **Search** の欄は、Scene で Hierarchy を絞り込むのと同じように、名前で絞り込みます。型の指定（Unity エディタと同じ `t:Material`）で、1 つの型だけにできます。型の名前、基底の型の名前（`t:Texture` ならテクスチャすべて）、フォルダー（`t:data`）が使えます。検索中は、合うものがあるフォルダーだけを「合う数 of 全体の数」つきで並べ、開いておきます。検索中に閉じたフォルダーは、検索の文字を変えるまで閉じたままです。
- **Close all** で、すべてのフォルダーを閉じます。
- 名前のないオブジェクトは、型と一緒に `(no name)` と出します。
- Unity が隠しているオブジェクト（`HideFlags.HideInHierarchy` か `HideInInspector`。`HideAndDontSave` にはこれが含まれます）は、**Show hidden** をオンにしたときだけ出します。既定はオフです。ほかの場所から隠れたオブジェクトを選ぶと、オンになります。
- 行を描くのは画面に見えている部分だけです。何万件あるフォルダーでも、短い一覧と同じようにスクロールできます。

### 右の欄：選んだオブジェクト

今までの中身の欄を、どのオブジェクトにも使います。公開のフィールドとプロパティを出し、非公開のものは **Show private** の後ろに置きます。操作もエラーの扱いも同じです。ただし、Unity が読むたびにコピーする配列のプロパティ（メッシュの `vertices`、`uv`、`triangles`、クリップの `events`、コントローラーの `animationClips`）は行に出しません。毎フレーム読むと、毎フレームコピーすることになるからです。代わりに、見出しにその数を出します。

その上に見出しを付けます。フォルダーと名前、そして種類ごとの数行です。オブジェクトを選んだときに 1 回だけ計算します。

| 種類 | 見出し |
|---|---|
| テクスチャ | サイズ、形式、次元、CPU から読めるか、ミップの段数、フィルターとラップのモード。2D テクスチャのプレビュー。**Assets tab**（`Texture2D` のとき）で Assets タブを開きます。Mod が同梱した差し替えはそちらに出ます |
| スプライト | テクスチャの中での四角形、ピボット、1 単位あたりのピクセル数、パックされているか。テクスチャのうちスプライトの部分のプレビュー。そのテクスチャの **Assets tab** |
| マテリアル | シェーダーと、シーンの中でそれを共有している Renderer の数。行は Scene と同じく、シェーダーのプロパティとキーワード |
| シェーダー | プロパティ（名前は最初の 24 個まで）、キーワード、それを使っている読み込み済みのマテリアルの数、パスの数とレンダーキュー |
| メッシュ | 頂点数・三角形数・サブメッシュ数・ブレンドシェイプ数、読めるかどうか、範囲（bounds） |
| AudioClip | 長さ、チャンネル数、周波数、サンプル数、読み込みの種類と状態（オーディオのモジュールを参照していないので、リフレクションで読みます） |
| AnimationClip | 長さ、フレームレート、ループ、イベント（Animator の Clips と同じ）。コントローラーならクリップの数 |
| フォント | ダイナミックかどうか、サイズと行の高さ。TextMeshPro のフォントには追加の行はありません |
| ScriptableObject | 追加なし。フィールドそのものが見どころで、コンポーネントと同じように行になります |
| シーン外の GameObject | 読み取り専用であること、コンポーネントと子の数、そして Scene が中身の上に出しているのと同じコンポーネントのボタンの列（読み取り専用。[編集](#編集)を参照） |

見出しの下に、**Used by** と、使える場合は **Assets tab** のボタンを出します。

### Used by（どこで使われているか）

**Used by** は、選んだものが使われている場所を、中身の欄の代わりに（History と同じように）一覧にします。**Look again** と **< Members** があります。たくさんのオブジェクトを調べるので、ボタンを押したときだけ動きます。探す場所は 2 種類です。

1 つ目は、Unity が自分の（ネイティブの）コンポーネントやアセットに持っているものです。プロパティで尋ねます。

| 選んだもの | 探す場所 |
|---|---|
| マテリアル | Renderer の `sharedMaterials` |
| テクスチャ | すべてのマテリアルのテクスチャのプロパティ、スプライトの `texture` |
| スプライト | `SpriteRenderer.sprite` |
| シェーダー | マテリアルの `shader` |
| メッシュ | `MeshFilter.sharedMesh`、`SkinnedMeshRenderer.sharedMesh`、`MeshCollider.sharedMesh`（物理のモジュールを参照していないので、リフレクションで） |
| AudioClip | `AudioSource.clip`（リフレクションで） |
| AnimationClip | コントローラーの `animationClips`、古い `Animation` コンポーネントのステート（リフレクションで） |
| Animator のコントローラー | `Animator.runtimeAnimatorController`（リフレクションで） |

2 つ目は、どの種類でも、スクリプトがフィールドに持っているものです。すべての `MonoBehaviour`（シーンの中と外）とすべての `ScriptableObject` について、その型にそのオブジェクトを持てるフィールドがあれば調べます。フィールドそのもの、それの配列や `List<T>`、フィールドが持つ `[Serializable]` なクラスのフィールド（1 段だけ。UI の `Text` はフォントをそう持っています）です。ある型のオブジェクトを持てるフィールドは、持つ側の型ごとに 1 回だけ探して覚えておきます。UI の `Image`（スプライト）、`RawImage`（テクスチャ）、`Graphic`（マテリアル）、TextMeshPro のテキスト（フォントとマテリアル）、TextMeshPro のフォントアセット（アトラスのテクスチャとマテリアル）、ゲーム自身のスクリプトとデータは、これで見つかります。Unity の UI はこれらを非公開のフィールド（`m_Sprite`、`m_Material`）に持っているので、`Graphic.material` のようなプロパティ（何も設定されていないと既定のマテリアルを返します）ではなく、フィールドを読みます。

- 見つかった場所は 1 行ずつ出します。場所（コンポーネントならパスと型、アセットならフォルダーと名前。シーンの外のものは薄く出し、そう書きます）と、メンバー（`sharedMaterials[2]`、`m_Sprite`、`m_FontData.m_Font`）です。**Go** でそれを選びます。シーンのコンポーネントなら **Scene** で、アセットやシーン外の GameObject なら **Objects** で選びます。
- 2,000 か所で打ち切り、そう書きます。一覧の上の行に、調べたオブジェクトの数とかかった時間を出します。
- Used by のあとは、見出しのボタンが **Used by (N)** になり、共有されているものには「N か所で使われていて、変更はそのすべてに出る」と出します。
- コードからしか使われていないもの（または今は何にも使われていないもの）は、空の一覧と、どこを探したかを出します。

### Scene との行き来

- 中身の欄の `UnityEngine.Object` の行には、今まで Inspector が知っていた種類に限らず、すべてに **Go** を付けます。シーンのオブジェクトやコンポーネントの Go は Scene でそれを選び、それ以外（テクスチャ、メッシュ、クリップ、ScriptableObject、プレハブ）の Go は Objects で、そのフォルダーを開き、そこまでスクロールして開きます。
- テクスチャの行には、Assets タブへの道も残します。Go の隣の 2 つ目のボタン **Assets** です。
- `Inspector.Inspect(UnityEngine.Object)` は、どのオブジェクトでも受け付け、合う表示で開きます。シーンのオブジェクトやコンポーネントは Scene、マテリアルは今開いている表示、それ以外は Objects です。
- Assets タブでテクスチャの **Inspect** を押すと、Objects でそのテクスチャを開きます（前は、それを使う最初のマテリアルを開き、使うマテリアルがあるときだけボタンが出ていました）。その Used by に、使っているマテリアルとスプライトが出ます。

## 編集

Scene と同じ行、同じ規則です。足すのは 2 つです。

- **共有されているもの。** アセットはふつう、たくさんのオブジェクトから使われています。マテリアル、テクスチャのフィルターモード、ScriptableObject の値を変えると、それを使っている所すべてが変わります。**Used by** を実行したあとは、見出しに使っている場所の数を出します。また、共有されているものを最初に編集したときに、1 回だけ、状態の行でそのことを知らせます。
- **シーンの外にあるオブジェクトは、そのコンポーネントも含めて読み取り専用です。** ゲームが読み込んだままのプレハブを変えると、そこから後で作られるものすべてが変わり、気づきにくく、元に戻しにくいからです。行は表示しますが、編集はできません。Enabled のボタン、Rigidbody と Animator のボタンも出しません。本当に必要になったら、専用の警告つきのスイッチにします。

編集は Scene と同じく **History** に入り、Revert と Redo ができます。フォルダーと名前で示します（`Materials: Counter (Material)`）。**Export as overrides** は、理由を添えてこれらを外します。オーバーライドはシーンの中の場所を指すもので、Objects での編集はアセットそのものの編集だからです。ファイルには何も書きません。

## 一覧の作り方

- `Resources.FindObjectsOfTypeAll<UnityEngine.Object>()` を 1 回たどり、フォルダーに振り分け、（Data と Other では）型ごと、そして名前順に並べます。動くのは、Objects を初めて見たとき、**Refresh** を押したとき、シーンの読み込みや解放のあとにもう一度見たときです（Hierarchy と同じイベント。Objects、コンソールの `objects`、操作のどれもが「見る」にあたります）。毎フレームは動かさず、誰も見ていなければ動きません。型での絞り込みは、その一覧を絞り込むだけです。
- **一覧はアセットを生かし続けません。** Unity の `Resources.UnloadUnusedAssets` は、マネージドコードが参照しているアセットを解放しません。参照の一覧を持つと、ゲームが次の場面に進んだあとも、前のシーンのアセットがメモリに残ってしまいます。
  - そのため一覧には、インスタンス ID、名前、型、短い情報だけを持ちます。`FindObjectsOfTypeAll` の配列は、1 回たどり終えたところで手放します。
  - オブジェクトを ID から探し直すのは、選んだとき、その行を初めて描くとき、Used by が指したときです。
  - Unity 6.3 では `Resources.EntityIdToObject` で探せます（`InstanceIDToObject` は 6.3 では古い形式になりました）。インスタンス ID は `EntityId` に変換できるので、代わりの方法は要りませんでした。
- 選んでいる間だけは、Scene と同じく選択そのものを参照で持ちます。
- 一覧を作ったあとに Unity が破棄したオブジェクトは、その行に `(destroyed)` と出します。選ぶとそう知らせ、Refresh を勧めます。選んでいたオブジェクトを Unity が破棄したときは、Scene と同じく、メモを出して選択を外します。一覧を作ったあとにできたオブジェクトは、何かがそれを選んだときに、1 回だけ並べ直して見つけます。

## 速さ

ゲームには、読み込まれたオブジェクトが何万もあります。何にどれだけかかるかです。

- **1 回たどる処理**は、ほとんどが Unity 自身の `FindObjectsOfTypeAll` と、それぞれの名前の読み取りです。毎回ログに出し（`[objects] Listed N objects in X ms (FindObjectsOfTypeAll Y ms)`）、状態の行にも出すので、ゲームの中では毎回測られます。この数字はゲームの中で取る必要があります（ゲームでの確認を参照）。
- **並べ替え、検索、行の組み立て**は、一覧のコードそのもの（`InspectorObjectList.cs`。Unity の型を使っていません）を、ゲームに似せて作った一覧（テクスチャが 5 分の 1、データが 15% で 50 の型、名前は 2〜4 語、20 件に 1 件が隠れたもの）で、ゲームの外で測りました。.NET Framework 4.7.2、リリースビルド、21 回の中央値、オーナーの開発用 PC です（ゲームの Mono はこれより遅いので、2〜3 倍と見込んでください）。

| オブジェクト数 | 並べ替え（1 回たどるごと） | 行、フォルダーを閉じたまま | 行、4 つ開いたとき | 名前で検索 | `t:Materials` | "a" で検索、隠れたものも |
|---:|---:|---:|---:|---:|---:|---:|
| 20,000 | 7 ms | 0.2 ms | 0.2 ms | 1.9 ms | 0.3 ms | 1.7 ms |
| 60,000 | 26 ms | 0.6 ms | 1.0 ms | 6.1 ms | 1.0 ms | 6.8 ms |
| 200,000 | 106 ms | 3.1 ms | 5.9 ms | 25 ms | 4.5 ms | 31 ms |

- 行を作り直すのは、検索の文字、フォルダー、Show hidden、一覧のどれかが変わったときだけで、毎フレームではありません。描くのは画面に見えている行（30 行ほど）だけで、行の短い情報は 1 回だけ読みます。検索で 1 文字打つと行の組み立てが 1 回、スクロールは短い一覧と同じ負担です。
- 行の組み立ての最初の版は、オブジェクトごとに文字列のキーで数を引いていて、検索なしでも 4〜5 倍かかっていました（60,000 件で、閉じたまま 4.2 ms、開いて 4.8 ms）。フォルダーごと・型ごとにその場で数えるようにして、上の表の数字になりました。
- **Used by** は、必要な種類のときだけ Renderer、マテリアル、スプライトなどをたどり、そのあとすべての MonoBehaviour と ScriptableObject を 1 回ずつ見ます。読むのは、選んだ型を持てるフィールドだけです（持つ側の型ごとに 1 回だけ探します）。かかった時間はログと一覧の上に出します。これもゲームの中で数字を取る必要があります。
- 見出し、短い情報、Used by は、選んだオブジェクトか、画面に見えている行にだけ計算します。Objects を閉じていれば、何も動きません。

## 安全

- **開発者ツールのときだけ。** Inspector のほかの部分と同じです。
- **アップロードなし。** プレビューは、ゲームがすでに読み込んだテクスチャを描くだけです（Assets タブのプレビューと同じ `GUI.DrawTextureWithTexCoords`）。作成・読み戻し・アップロードはしないので、Direct3D 12 の問題は起きません。GPU だけが持っているテクスチャも、読まずにそのまま描きます。
- **名前はウィンドウの保護を通して描く。** Tool window のほかの場所と同じです。
- **失敗はその行にとどめる。** プロパティの getter が例外を出しても（Unity のオブジェクトには、当てはまらないプロパティで例外を出すものがあります）、その行に出して一覧は続けます。並べる途中で失敗したオブジェクトは外し、見出しの行で失敗したときはそう書きます。
- **重い処理は押したときだけ。** 一覧、Used by、プレビューは、ボタンを押したときか選んだオブジェクトにだけ動きます。Objects を閉じて遊んでいる間の負担はありません。

## コンソール

- `objects` でフォルダーと件数（と隠れている数）を表示します。`objects <種類> [絞り込み]` で合うオブジェクトを最大 200 件並べます（例：`objects materials counter`、`objects textures t:RenderTexture`）。
- `inspect object <種類> <名前>` で、Objects のオブジェクトを選び、ウィンドウを開いて、その見出しを表示します。
- `objects usedby <種類> <名前>` で、Used by の一覧を表示します（コンソールでは最大 200 か所）。
- 種類は、フォルダーの名前か短い言葉です。`textures`、`sprites`、`materials`、`shaders`、`meshes`、`audio`、`animation`、`fonts`、`data`、`outside`、`other`（`material`、`clip`、`prefab` のような単数形も使えます）。名前は、名前全体か、その種類でそのオブジェクトだけが持つ一部です。補完で種類と名前を出します。

## 操作

操作の登録簿（[API_PLAN.ja.md](API_PLAN.ja.md) の段階 1）に、読むだけの操作を足しました。コンソールの `op` と Bridge の AI クライアントが、同じことを尋ねられます。

| 操作 | 引数 | 返すもの |
|---|---|---|
| `inspector.loaded.kinds` | | フォルダーごとの件数と隠れている数、並べるのにかかった時間 |
| `inspector.loaded.list` | `kind`（必須）、`filter`（名前の一部、`t:型`）、`hidden`、`max`（1〜1000、既定 200） | `{ name, type, fact, id }` |
| `inspector.loaded.usedby` | `kind`（必須）、`name` か `id`、`max`（1〜2000、既定 200） | `{ object, summary, places: { where, member, in_scene } }` |

`inspector.selection.get` は、Objects で選んでいるものも返します（`{ view: "objects", object, kind, target }`）。返すのは名前、型、大きさ、場所で、オブジェクトの中身は返しません。

## 作る順番

6 段階すべてを `experimental/object-explorer-build` で作りました。

1. Scene | Objects の切り替え。種類別の一覧と件数、検索と `t:`。今までの中身の欄での表示。Scene の行からすべての種類への Go。`Inspector.Inspect` をどのオブジェクトでも使えるように。
2. 種類ごとの見出しと、テクスチャ・スプライトのプレビュー。
3. Used by。
4. 共有の知らせつきの編集と History。
5. コンソールのコマンドと、読むだけの操作。
6. Show hidden と、Data（と Other）の型ごとのサブフォルダー。

後で考えるもの（この設計には入れない）：音の再生、書き出し（アセットツールの 3 番目）、Mod に同梱するマテリアルの差し替え（Assets ライブラリ）、一覧のパス以外でプレハブの子をたどる方法。

## 決めたこと

2026-09-20、最初の版をゲームで動かしたあとに、オーナーが決めました。どれも作ったままを残します。

1. **シーンの外にある GameObject は、読み取り専用のままにします。** それはゲームがオブジェクトを作る元なので、そこを変えると、あとから作られるもの全部に出てしまい、戻すのも難しくなります。変えるなら、シーンの中のオブジェクトを変えます。
2. **一覧は、場面の読み込み時と Refresh のときに作ります。** 定期的には作り直しません。数千件を並べるのに数ミリ秒かかりますが、それを毎秒払っても得るものがありません。
3. **Unity が隠しているオブジェクト（HideFlags）は、Show hidden を押すまで出しません。** ほとんどは Unity 自身のもので、探しているものより数が多いからです。
4. **新しい読み取り操作 `inspector.loaded.*` は、AI クライアントにも出したままにします。** 読み込まれているものを読むだけで、ゲームのコードは見せません。コードを見せるのはページ専用の `code.*` です。
