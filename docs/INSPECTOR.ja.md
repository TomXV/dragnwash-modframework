# Inspector（設計）

[English](INSPECTOR.md)

> **実験的な機能です。** Tool window の上に載る独立したライブラリ `DragNWash.ModFramework.Inspector`（1.0.0）として作り、フレームワーク 1.2.0 でリリースしました。**リリース後も実験的な機能のまま**です。変わったりなくなったりすることがあり、これで加えた編集は動いているセッションを壊すことがあります。フレームワークのリリースには同梱し、Mod のリリース（たとえば Drag'n Wash Localization）は Tool window だけを同梱して Inspector を外せます。使ってみて足したもの：**Pick**（ゲーム内のオブジェクトをクリックして選ぶ。uGUI の要素を先に、次にポインターの周りで画面上の bounds が最も小さい Renderer。コライダーは要りません）、**Highlight**（選んだオブジェクトをゲーム内で枠で囲む）、ベクトル・色・rect・bounds の成分ごとの入力欄、色見本から開くカラーピッカー（彩度×明度の正方形と色相バー、RGBA のバー、16 進）、枠の名前タグとピック中のホイールでの候補切り替え、コンポーネントごとの **Code** 表示（型、Harmony 用の名前をコピーできるメソッド一覧、**Patch** ボタンで Harmony パッチ一式（`GameHooks.Require` の確認、名前だけでは曖昧なときは引数の型も入った属性、Harmony が渡してくれる引数を持つ Prefix と Postfix）をコピー、それらに当たっている Harmony パッチと持ち主、UnityEvent のリスナー、Mono.Cecil で読んだメソッドの IL。C# への逆コンパイルはせず、そこは手元の dnSpy や ILSpy に任せます）、**デバッグ表示**（カメラに映るすべて、選択の子孫、または検索に合うものを一度に枠で。コライダー・トリガー・ライトも（シーン全体、または選択中のものだけ）。コライダーとライトはその形のまま描きます（Box は箱、Sphere は球、Capsule はカプセル、MeshCollider はワイヤーフレームか頂点の点。形を物理エンジンだけが持っている場合は、範囲の 6 方向から格子状にレイをそのコライダーだけに当て（Collider.Raycast）、深度カメラのように形を写し取って描く。**写し取った形はシミュレーションで、実際のデータではない。細い部分、レイが届かないくぼみ、細かい形は写らないことがあり、実物とは異なる場合がある。** ラベルにもそう表示する。うまくいかなければ箱。スポットライトは円錐、それ以外は bounds）。画面上の四角や 3D の箱も出せ、種類で色分けし、ポインターの近くに名前）、**Bones**（アーマチュアをゲーム画面に描き、関節をクリックするとそのボーンを選択）、**Wire**（メッシュをワイヤーフレームで。読めないメッシュは bounds の箱だけ）、**Edit mesh**（**Inspector の中でもさらに実験的な機能**で、メニュー・ボタン・使用中のタブにもそう表示します。読めるメッシュの頂点を、カメラに向いた面の上でドラッグ。メッシュのコピーに対して行い、History と Reset mesh あり。スキンメッシュと GPU 専用のメッシュは編集できず、ファイルには何も保存しません）、**フリーカメラ**（ゲームのカメラのコピーを、Unity のシーンビューと同じく右ボタンを押したまま飛ばす。その間ゲームのカメラは無効で、止めると戻る）、トランスフォームのギズモ（**Move** / **Rotate** / **Scale**：ゲーム画面にオブジェクトのローカル軸を出し、先端のハンドルをドラッグして動かす。位置・回転・スケールの読み出しと **Reset transform**）、編集した行ごとの **Reset**（最初の編集の前の値に戻す）、このセッションの編集をすべて並べる **History**（変更前と変更後、項目ごとの Revert / Redo、Undo last。ギズモのドラッグも入ります）、行の右クリックメニュー（元の値、直前の値、コピー）、**Parent** ボタン、選択に追従するヒエラルキー。テクスチャのプロパティの **Go** は Assets タブをそのテクスチャに絞って開き、Assets タブのテクスチャの行の **Inspect** は、それを使っている最初のマテリアルを開きます。

## 導入

手動での導入が必要です。Inspector は、Mod に同梱されるインストーラーには入っておらず、Drag'n Wash Localization にも入っていません。使うときは、[フレームワークのリリース](https://github.com/TomXV/dragnwash-modframework/releases)から `DragNWash.ModFramework-<バージョン>.zip` をダウンロードし、中の `BepInEx/plugins/DragNWash.ModFramework.Inspector` フォルダーを、ゲームの `BepInEx/plugins` フォルダーにコピーしてください。そのうえで **Developer tools**（Options → Mods → Drag'n Wash ModFramework）をオンにし、F1 を押します。外すときは、そのフォルダーを削除します。

Tool window の **Inspector** タブ。シーンのオブジェクトとそのコンポーネント、それぞれのフィールドとプロパティ、読み込まれているマテリアルのパラメーターを、ゲームを動かしたまま読み、書き換えられるようにします。Unity のエディターの Inspector がやることを、ビルドしかないゲームに対して。Mod を作る人が「これは何で、何という名前で、どんな値を持っているか」を知り、コードを 1 行書く前に変更を試すためのものです。開発者ツールの中の機能（GUIDE のルール 8）で、遊ぶ人が目にすることはありません。

## 何のためで、何ではないか

- **調べる。** 看板の裏にあるオブジェクトの名前、扉を動かすコンポーネント、カウンターのマテリアルとそのシェーダー、洗う速さを持つフィールド。Mod の `GameHooks.Require` や `AssetReplacements` に名前が要るものすべてを、逆コンパイルではなく見て探せます。
- **試す。** 値を変えると、すぐゲームに出ます。保存はしません。変更はシーンの読み直しかゲームの終了までのものです。変更のまとまりを Mod にすることは別の設計です（起動時に Assets ライブラリが当てる上書きファイル。テクスチャの差し替えと同じやり方）。ここでは意図的にやりません。2 つを別々に判断できるようにするためです。
- **RuntimeUnityEditor ではありません。** REPL、引数付きのメソッド呼び出し、コンポーネントの追加と削除、プレハブの生成、ギズモはありません。それらは RuntimeUnityEditor がよくできています。ただしあちらは独自の IMGUI 窓を開き、カーソルと入力を奪うので、Tool window とはぶつかります。FAQ にそう書きます。共存を検証するまでは、どちらか一方で。

## どこに置くか

**Tool window** ライブラリ（Tool window 1.2.0）のタブとして。ゲームからも、ほかのライブラリからも何も要りません。リフレクションと、Unity 自身のシーンとシェーダーの API で足ります。マテリアルの部分は、Assets ライブラリが読み込まれていれば `AssetCatalog` を読みます。今の Assets タブが Tool window を読むのと同じ形（chainloader で確かめる弱い依存で、直接参照しない）です。Assets タブにはマテリアルごとに **Inspect** ボタンが付き、ここに飛びます。

## タブ

左から右に 3 つの区画。狭い窓では、Saves タブの行と同じように、戻るボタン付きの 3 ページになります。

1. **ヒエラルキー。** 読み込まれているすべてのシーン、そのルートのオブジェクトと子を木で。**Search** の入力欄で名前で絞り込み（部分一致、大文字小文字を区別しない）、一致したものをパス付きの平らな一覧にします。非アクティブなオブジェクトは薄い色。木を組むのは、タブを開いたとき、**Refresh** を押したとき、シーンが読み込まれたとき（`GameEvents.OnSceneLoaded`）だけで、毎フレームではありません。シーンには何千ものオブジェクトがあり、`FindObjectsOfType` は安くありません。
2. **コンポーネント。** 選んだオブジェクトのコンポーネントを順に。上にオブジェクトのアクティブ状態、タグ、レイヤー、フルパス。Renderer の **Materials** はコンポーネントのように並ぶので、マテリアルは、それを表示しているオブジェクトから 1 クリックです。コンポーネントを選ぶと 3 つ目の区画に開きます。
3. **メンバー。** コンポーネントのフィールドとプロパティを 1 行ずつ。名前、型、値。public を先に、非公開は **Show private** の切り替えの下に（既定はオフ。非公開フィールド経由で値を入れるのは Mod 作者自身の責任で、ページに一度そう出ます）。値は選んでいるコンポーネントについてだけ Repaint ごとに読むので、ゲームが動けば数字も動きます。毎フレーム変わる値を読むための **Freeze** の切り替えがあります。

## 編集

タブが知っている型の行には操作が付きます。ほかは値を文字で示すだけで、読み取り専用です。

| 型 | 操作 |
|---|---|
| `bool` | トグル |
| `int`、`float`、`double`、`long` などの数値 | 入力欄。Enter で反映。パーサーが受け付けない値は元に戻り、行に理由が出る（Mods 画面の設定ページと同じ規則） |
| `string` | 入力欄 |
| 列挙型 | ボタンで順に切り替え、値が多ければ一覧 |
| `Vector2/3/4`、`Quaternion`（オイラー角で表示）、`Rect`、`Bounds` | 成分ごとの入力欄 |
| `Color` | 4 つの入力欄と色見本 |
| `UnityEngine.Object` の参照（Transform、Material、Texture、別のコンポーネント） | 名前と、それを選ぶ **Go** ボタン。編集不可 |
| 上記のリストと配列 | 展開して要素ごとに 1 行。追加と削除はなし |
| それ以外 | `ToString()`、読み取り専用 |

プロパティは setter があるときだけ編集できます。すべての代入は try/catch の中で行い、ゲームの setter が投げた例外はその行に出て、タブは続きます。`Transform` もほかのコンポーネントと同じ行（`position`、`rotation`、`localScale`）で、特別扱いはしません。

## マテリアルとシェーダー

マテリアル（Renderer から、または Assets タブから）を選ぶと、メンバーの区画にはシェーダー自身に聞いたプロパティ（`Shader.GetPropertyCount`、`GetPropertyName`、`GetPropertyType`、Range の上下限）が、マテリアルの現在の値とともに並びます。

| プロパティの型 | 操作 |
|---|---|
| Float、Range | 入力欄。Range は上下限を表示 |
| Color | 4 つの入力欄と色見本 |
| Vector | 4 つの入力欄 |
| Texture | テクスチャの名前、サイズ、形式と、Assets タブへの **Go**。ここでは編集不可（テクスチャの差し替えはすでにあり、専用の安全な経路を通ります） |
| Int | 入力欄 |

シェーダーキーワード（`_ALPHATEST_ON` など）はそれぞれトグル付きで並びます。マテリアルを変えると、それを共有するすべての Renderer が変わります。Mod のマテリアル上書きでも同じことが起きるので、区画には共有している Renderer の数が出ます。

保存できるようになる前でも作る価値があるのは、この部分のためです。ここで見つけた色や smoothness の値は、のちの上書きファイルに書くものそのもので、翻訳者のテクスチャ作業も、それを表示しているマテリアルから Go ボタン 1 つの距離になります。

## Rigidbody

実験的。ゲームは Rigidbody で物を動かします（たとえばマスばねのコントローラーが力を加えて動かします）。そこで Inspector は Rigidbody を読み、一覧にし、いくつかのスイッチを操作します。物理モジュールは参照しません。`Rigidbody` と `Rigidbody2D` はコライダーと同じく名前で探してリフレクションで読むので、モジュールがなくてもライブラリは読み込めます。Unity 6 で `velocity` が `linearVelocity` に名前が変わったので、両方を試します。

- **デバッグ表示。** 表示 → **Rigidbodies: centre of mass and velocity** で、各ボディの重心に十字、進む向きに矢印（いまの速度で 0.25 秒ぶん進む長さ）を描き、速さ・回転の速さ・質量・種類（dynamic、kinematic、static）・スリープ中かをタグに出します。スリープ中のボディは灰色です。**of the selection only** で、コライダーやライトと同じく、選択とその子だけに絞れます。
- **一覧。** 表示 → **Rigidbodies list** で、シーンの（または選択の下の）有効な Rigidbody と Rigidbody2D を、History と同じくメンバーの代わりに出します。名前・型・いまの動きを速い順に並べ、**Awake only** と名前・型での絞り込みがあります。**Select** でボディを開き、一覧は開いたままなので順に見ていけます。
- **操作。** Rigidbody か Rigidbody2D を選ぶと、いまの動きを示す行と、メンバーの上にボタンが出ます。**Stop**（速度と回転を 0 に）、**Kinematic**（オンとオフ。`isKinematic`、Rigidbody2D では `bodyType`。History に残るので Revert で戻せます）、**Sleep** / **Wake**。
- **Pause physics**（Inspector の中でもさらに実験的）。`Physics.simulationMode` と `Physics2D.simulationMode` を Script にしてボディをその場に止め、**Step** で物理を固定ステップ 1 つぶん進めます（`Physics.Simulate(Time.fixedDeltaTime)`）。ゲームのスクリプトは動き続けるので、その間に加えられた力は次のステップで効きます。**Resume physics**、窓を閉じる、開発者ツールをオフにする、のどれでも、モードはゲームが持っていた値に戻ります。

## Animator

実験的。ゲームは、キャラクターを Animator で動かします。多くは、パラメーター（Bool、Float、Trigger）とレイヤーの重みを変えることで操っています。Rigidbody と同じく、Animator もリフレクションで読み、アニメーションのモジュールは参照しません。

- **パラメーターとレイヤーの重み**は、選んだ Animator のメンバーの先頭に行として並びます。数値はドラッグで、Bool は切り替えで変えられます。Trigger は true でセット、false でリセットです。ほかのメンバーと同じく History に残ります。ゲームは多くのパラメーターを毎フレーム書き込むので、そういうパラメーターを変えても、ゲームの次の書き込みまでしか続きません。
- **いま流れているもの**：行の上に、Base Layer の 1 行を出します。**Layers** で、メンバーの代わりに全部のレイヤーを一覧にします（竜は 10 以上あります）。レイヤーごとに 1 行ずつ、重み、流れているクリップ（ブレンド中はそれぞれの重みも）、ステートをどこまで進んだか、ブレンド先のクリップを出します。
- **Pause animation** で、Animator の速さを 0 にし、元の速さを覚えておきます。**Step** で 1/30 秒ずつ進み、Layers の中のレイヤーごとのスライダーで、いまのステートを好きな位置に置けます。**Resume animation**、窓を閉じる、開発者ツールをオフにする、のどれでも元の速さに戻ります。
- ゲームの中ではできないこと：ステートマシン（ステートと遷移）と、クリップの中のカーブは、Unity のエディターにしかありません。ステートは番号（ハッシュ）でしか分からないので、流れているクリップの名前でステートを見分けます。
- **Clips**（Animator のボタンの 1 つ）：メンバーの代わりに、コントローラーのクリップを一覧にします。それぞれの長さ、フレームレート、ループするか、イベント、何に差し替えているかを出します。**Preview** で、クリップをその Animator に、コントローラーとは別のグラフで流します。時間のスライダー、一時停止、**Stop preview** があります。**Replace** で、メモリーに読み込まれているクリップを全部並べ、**Use** でコントローラーがそちらを流すようにします（ゲームのコントローラーをもとにした AnimatorOverrideController）。**The game's clip** で元に戻ります。差し替えは History に残り（Revert で 1 つ前に戻る）、Animator のステートは最初からになります。Overrides の設計（`experimental/overrides` ブランチ）ともつながります。差し替えは、オーバーライドが残すような編集です。

## 安全策

- **開発者ツールの中だけ。** 窓のほかの部分と同じく、スイッチがオンの間だけタブがあります。
- **アップロードなし。** 値の読み書きでテクスチャを作ったり送ったりすることはないので、ここでは Direct3D 12 の心配はありません。テクスチャのプロパティは表示だけで、代入しません。
- **名前は窓の守りを通す。** オブジェクトの名前は何でもありえます。Direct3D 12 では Console と同じく ASCII 以外を `?` で出します。
- **破棄されたオブジェクト。** Unity が破棄した（`== null`）オブジェクトやコンポーネントを選んでいたら、例外ではなく、注記つきで選択を外します。
- **毎フレーム走査しない。** ヒエラルキーは求められたときに組みます。リフレクションのメンバー一覧は型ごとにキャッシュします。Repaint ごとに読むのは選んでいるコンポーネントの値だけです。
- **何も残らない。** ファイルも設定も、起動時の再生もありません。編集で起きる最悪のことは動いているセッションが壊れることで、再起動で直ります。タブを最初に開いたときに一度そう出ます。
- **分離。** リフレクションの失敗、setter の例外、投げるシェーダーの問い合わせは、行ごとに捕まえてその行に出します。

## Console

- `inspect` でヒエラルキーのルートを一覧。`inspect <名前またはパス>` でオブジェクトを選び（パスの区切りは `/`。パスでなければ名前の最初の一致）、タブをそこに開く。`inspect <パス> <コンポーネント>` でコンポーネントを選ぶ。
- `inspect set <パス> <コンポーネント> <メンバー> <値>` で、行と同じ解釈で Console から 1 つの値を入れる。手で打つ用で、スクリプト言語は相変わらずありません。
- 補完は、いまの検索に合うオブジェクト名と、パスのあとにそのコンポーネント名を出します。
- `bodies` でシーンの Rigidbody を速い順に、速さ・質量・種類・スリープとともに一覧。`bodies pause`、`bodies resume`、`bodies step [回数]` で物理の一時停止を操作します（実験的）。

## Mod 作者向け

- `Inspector.Inspect(UnityEngine.Object target)` で、オブジェクト、コンポーネント、マテリアルを選んでタブを開けます。Mod 自身のタブで、一覧の横に **Inspect** ボタンを置けます。
- 宣言は不要です。Mod 自身のものも含め、すべてのオブジェクトとコンポーネントが出ます。Unity の `[HideInInspector]` 属性が付いたフィールドは隠します。隠したい Mod はそれを使ってください。
- 型ごとの独自の描画（既定の行より気の利いた操作）はこの設計に含めません。必要が出てきたら、ほかと同じく GUID で登録する形になります。

## 順番

1. 検索と選択付きのヒエラルキー、コンポーネントの区画、読み取り専用のメンバーの区画。これだけでも名前を探すのに役立ちます。
2. 既知の型の編集と、行ごとのエラーの規則。
3. マテリアル：シェーダーのプロパティとキーワード、Assets タブの Inspect ボタン、テクスチャのプロパティから Assets タブへの Go。
4. `inspect` コマンドと補完、`ToolWindow.Inspect`。
5. 切り替えの下の非公開メンバー、リストと配列。
6. RuntimeUnityEditor についての FAQ と、求められれば共存の検証。

この設計に含めないもの：編集の保存（Assets ライブラリでの上書きの設計は後で）、メソッドの呼び出し、コンポーネントの追加と削除、プレハブ、ギズモ、REPL。
