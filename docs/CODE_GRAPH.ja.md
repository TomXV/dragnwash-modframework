# コードのグラフ：ゲームのコードをノードで見る

[English](CODE_GRAPH.md)

> **作りました**（実験的、2026-09-19）。[API の計画](API_PLAN.ja.md)の第 3 段階で、ブランチ `experimental/code-graph` にあります。Windows のゲームの中で試しました。ページの見た目と Steam Deck は、まだ試していません。調査でわかったことは[調査](#調査)にあります。

Inspector の Code 表示は、コンポーネントのメソッド、それに付いた Harmony のパッチ、メソッドの IL を、F1 の窓に行として並べます。コードのグラフは、同じコードを図にします。メソッドのブロックと分岐、呼ぶもの、読み書きするフィールド、誰のパッチが付いているか、どのイベントからそこへ来るか、です。呼び出しをクリックすると、そのメソッドが開きます。dnSpy なしで、「どこに差し込めばよいか」「このメソッドがほかに何に触るか」を知りたい Mod の作り手のためのものです。

## 決めたこと（2026-09-19）

- **この PC の Bridge が出す、ブラウザーのページで。** F1 の窓ではありません。IMGUI で図を描くと重く、Direct3D 12 の文字の制限も受けます（[計画](API_PLAN.ja.md)で決めたとおり）。
- **ページだけで、MCP には出さない。** グラフは操作の 1 つですが、呼べるのはページだけで、AI クライアントからは見えません。ゲームのコードは Gator Dragon Games の作ったもので、[コンテンツの方針](CONTENT_POLICY.ja.md)はそれをこの PC の中に留めます。その一部（たとえば、誰が誰を呼ぶかだけ）を AI のサービスに見せるかどうかは、改めてそれだけで決めます。
- **F1 の窓から開く。** ボタンが一度きりの合言葉を作り、それをつけてページを開きます。ページはそれを自分専用の Cookie に替えます。トークンを貼り付ける必要はありません。
- **分岐まで。** メソッドは、呼び出しの図の 1 つのノードとしてだけでなく、基本ブロックとその分岐（if、ループ、switch、try）として描きます。

## 見せるもの

1 つのメソッド（*注目*するメソッド）について：

- **ブロック**：IL から作ったメソッドの基本ブロックを、順に並べます。各ブロックには、逆コンパイルせずに書ける言葉で、そのブロックがすることを出します。呼ぶメソッド、読み書きするフィールド、何を比べるか、何を返すか投げるか、です。IL は 1 クリックで見られます（F1 の窓が今出しているのと同じ IL です）。
- **分岐**：ブロックの間の矢印で、*true*／*false*、*case n*、*ループで戻る*、*catch*、*finally* のラベルがつきます。
- **呼び出し**：呼ぶメソッドを、それを呼ぶブロックの中に並べます。ゲームのメソッドはクリックで開きます。Unity と .NET のメソッドは出すだけで、開きません。
- **呼び出し元**：注目するメソッドを、ゲームのどのメソッドが呼ぶか（逆引きの索引をセッションに一度作ります）。
- **パッチ**：注目するメソッドと、呼ぶメソッドのそれぞれに付いた Harmony の prefix、postfix、transpiler、finalizer。持ち主の Mod を、Harmony の ID だけでなく Mods 画面の名前で出します。
- **イベント**：読み込まれたシーンの中で、注目するメソッドを呼ぶ UnityEvent のリスナーと、そのメソッドが起こす、または答えるフレームワークの `GameEvents`。
- **コルーチン**：`IEnumerator` を返すメソッドは、隠れたクラスを作るだけです。グラフはそのクラスの `MoveNext` までたどり、その状態をメソッドの本体として描きます。`yield` の 1 つ 1 つが、ラベルつきの矢印になります。`async` のメソッドも同じです。

1 つの型について：そのメソッドをノードとして、まとまり（`Update` などの Unity のメッセージ、public、private）ごとに並べ、その間の呼び出しを線にします。クリックすると、そのメソッドに注目します。

**構造であって、ソースではありません。** C# への逆コンパイルはしません（それは dnSpy と ILSpy の役目のままです）。ゲームのコードのどの部分も、ファイルに書くことはなく、この PC のページ以外へ送ることもありません。

## 部品

| 部品 | 置き場所 | すること |
|---|---|---|
| `code.graph`、`code.type`、`code.callers`、`code.search` | Inspector（操作） | ゲームのアセンブリを Mono.Cecil で読み（Code 表示と同じ）、グラフを JSON で返す。*ページだけ*の印つき。 |
| ページだけの操作 | 中核（`Operations`） | 操作の新しい印：*ページだけ*。MCP の `tools/list` と `tools/call` はこれを外します。Console の `op` とページは呼べます。 |
| ページ | Bridge | `GET /page`（HTML のファイル 1 つ。スクリプト、スタイル、図を描くコードはその中にあり、インターネットからは何も取りません）と、ページが呼ぶ `/page/api/…`。 |
| ページのサインイン | Bridge | 一度きりの合言葉から Cookie へ（下）。 |
| ボタン | Inspector | Code 表示の、メソッドごとの **Graph** と **Type graph**。Console では `op bridge.page.open focus=m:<メソッドの ID>` か `focus=t:<型>`。 |

配置はページ自身のコードで描きます。1 つのメソッドのブロックは多くても 79 なので（調査を参照）、簡単な層に分ける配置で足り、ライブラリを同梱することも取りに行くこともいりません。

## ページのサインイン

今の Bridge は、ウェブページを断ります（`null` 以外の `Origin` はすべて）。ページは Bridge 自身のアドレスのウェブページなので、MCP とは別に、専用の入り口を持たせます。

1. **Graph** が一度きりの合言葉（32 バイトの乱数。1 回だけ、60 秒）を作り、`http://127.0.0.1:<ポート>/page#<合言葉>` をシステムのブラウザーで開きます。
2. ページは `#` のあとの合言葉を読み（ブラウザーはこの部分をサーバーへ送らないので、どのログにも残りません）、アドレス欄から消して、`/page/api/login` に送ります。
3. Bridge は Cookie で答えます。`HttpOnly`、`SameSite=Strict`、`Path=/page` で、ゲームが動いている間だけ有効です。合言葉はこれで使い切りです。
4. そのあとの `/page/api/…` への呼び出しには、その Cookie **と**、Bridge 自身のアドレス（`http://127.0.0.1:<ポート>`）と同じ `Origin` が要ります。Host の確認は今のままです。ほかのサイトからは呼べません（`SameSite=Strict` なので、ほかのサイトからは Cookie が送られず、`Origin` も違います）。MCP の入り口は、この Cookie を受け付けません。
5. **New token** と、Bridge をオフにすることは、ページのサインインも終わらせます。

ページは、Bridge のほかの部分と同じく、この PC のためだけのものです。Steam Deck では、デスクトップモードのブラウザーで開きます。

## この段階でしないこと

コードを変えること、何かを書くこと。第 4 段階（グラフを組み立てる）は、のちに同じページを使います。Mod のコードは描きません。Mod はそのパッチ（持ち主とパッチのメソッド）として出るだけで、IL は出しません。デバッグ（ブレークポイント、1 行ずつ進める）は扱いません。

## 調査

2026-09-19 に、ゲームの外で、Mono.Cecil（`BepInEx/core` にあるもの）を使って `Assembly-CSharp.dll`（424 KB、2026-09-14 のゲームの更新のもの）を調べました。

| | |
|---|---|
| アセンブリを読む | 8 ミリ秒。すべてのメソッドをたどるのに 28 ミリ秒、すべてのメソッドのブロックを見つけるのに 15 ミリ秒 |
| 型 | 466。そのうち 56 はコンパイラが作ったもの |
| 本体のあるメソッド | 2385。ラムダ 10、状態機械（コルーチンと `async`）44 |
| メソッドあたりのブロック | 中央値 1、90 パーセンタイル 7、99 パーセンタイル 19、**最大 79** |
| メソッドあたりの命令 | 中央値 6、90 パーセンタイル 42、最大 527 |
| 呼び出しの箇所 | 8904。そのうちゲーム自身のアセンブリへは 2612 |
| フィールドの読み書き | 6537。デリゲートを作る箇所（`ldftn`）318 |
| `switch`／`try` | 21／108 |

つまり、アセンブリ全体の索引（呼び出し、呼び出し元）は一度に 50 ミリ秒ほどで作れて、グラフは小さく、コルーチンは専用の扱いが要るほど多い、ということです。ゲームには、スタジオや作者のアセンブリも入っています（`GatorDragonGamesExtensions`、`Naelstrof.*`、`RalivIK` など）。これらも同じように描きます。

**コルーチン**（同じ日に確かめました）：44 の状態機械（イテレーター 39、`async` 5）は、すべて、作る側のメソッドの `IteratorStateMachine`／`AsyncStateMachine` 属性からたどれます。`MoveNext` は、はじめに状態のフィールドを読んで分かれます。37 は比較の連なりで、7 は `switch` です（状態の多いもの）。再開する場所は、戻る直前にそのフィールドへ入れる定数で見分けられます（1 つの状態機械に中央値 1、多くて 12）。18 には `try`／`finally` があり、コンパイラはそれも状態で振り分けています。なので、ページは頭の振り分けを「*yield n のあとで再開*」という矢印に置き換え、残りをメソッドの本体として描けます。ほかのアセンブリの型を Cecil の `Resolve()` で解くには、ゲームの `Managed` フォルダーを見るアセンブリの解決役が要ります。ここでは完全な名前を比べれば足ります。

**ゲームの中で**（Windows、作ったもので）：

1. **ブラウザーを開く：動く。** `#` のあとに合言葉をつけて `Application.OpenURL` で開くと、既定のブラウザーが開き、`#` のあとも残っていました。ページはサインインできました。Steam Deck のデスクトップモードは、まだ試していません。
2. **Cookie と Origin：動く。** サインインのあとの呼び出しには、Cookie とページ自身の `Origin` がついていました。curl からは、`Origin` がないものやほかのサイトのものは 403、使い終わった合言葉や知らない合言葉は 403、Cookie がないものや作った Cookie は 401、違う Host は 403 でした。MCP の `tools/list` は前と同じ 22 のツールのままで、`code_graph` と `bridge_page_open` は知らないツールとして断られます。
3. **ブラウザーの後ろでゲームが止まる。** このゲームは、窓が前面にないと動きません。そのため、ページの最初の呼び出しは、ゲームをもう一度クリックするまで（46 秒）待たされました。Bridge は、待ち受けている間ゲームを動かし続けるようにしました（`Application.runInBackground`。止めると元に戻します）。そのあとは、呼び出しにすぐ答えました。
4. **UnityEvent のリスナー：軽い。** タイトル画面の 239 のコンポーネントを 2 ミリ秒で調べました。シーンを読み込むたびに一度調べます。
5. **パッチの持ち主：動く。** `MenuOptions.OnEvent` に当たったフレームワークの prefix は、`Drag'n Wash ModFramework` と出ました（`com.tomxv.dragnwash.modframework` から）。
6. **どのアセンブリか。** ゲームのフォルダーには、Unity のものでも .NET のものでもないアセンブリが 32 あります。そのうち 17 は、ほかのものに同梱されたライブラリ（YarnSpinner が持つ .NET のパッケージの写し、Protobuf、Steamworks など）なので外しました。残りは 15、メソッドは 5,891 で、索引は 82 ミリ秒で作れます。
7. **親の型を通した呼び出し。** `MenuOptions.OnEvent` を直接呼ぶところはなく、`Menu.OnEvent` を通して呼ばれます。上書きしている親のメソッドの呼び出し元も、「*Menu.OnEvent を通して*」の印つきで並べます。

呼び出しは、ブロックの横の別のノードではなく、ブロックの中に並べます（ゲームのメソッドはリンクになります）。1 つのブロックが呼ぶものは多くないので、このほうが図が読みやすいからです。
