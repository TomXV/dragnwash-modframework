# アセットの道具

[English](ASSET_TOOL.md)

> **実験的な機能です。** Assets ライブラリ 1.1.0 から `main` に入っていますが、まだリリースには含まれていません。リリースまでに内容が変わることがあります。

フレームワークはゲームのアセットを扱う道具を提供します。それで何を作るかは、REFramework などと同じく、使う人の責任です。次の 3 つを、この順で作ります。

1. **覗く**：読み込まれているテクスチャ、マテリアル、メッシュ、シェーダーの一覧
2. **差し替える**：Mod が自分のファイルを同梱し、ゲームのファイルには触らずに、ゲームのものと入れ替える
3. **取り出す・取り込む**（未実装）：読み込まれているものを平文のファイルに書き出し、手を加えて、Mod から取り込む

ここにあるものは、ゲームのアセットを配布しません。手を加えていないゲームのデータは、リポジトリにもリリースにも入れず、このリポジトリの CI が確かめます。手で作ったものや手を加えたものは [CONTENT_POLICY.ja.md](CONTENT_POLICY.ja.md) に従います。

## 覗く

`AssetCatalog.Textures()`、`Materials()`、`Meshes()`、`Shaders()` が、いま読み込まれているものを、名前、サイズ、形式、CPU から読めるか、使っているマテリアルとスプライトの数とともに一覧にします。その種類の読み込み済みオブジェクトをすべて走査するので、毎フレームではなく、ボタンを押したときに呼んでください。

Tool window ライブラリが入っていれば、**Assets** タブ（F1）で、テクスチャを絞り込み付きで一覧し、Mod が同梱した差し替えと、2 つの Mod がぶつかった場所を表示し、**Apply replacements** ボタンで当て直せます。

## 差し替える

差し替えたいゲームのテクスチャの名前で、PNG を Mod のフォルダに置きます。

```
BepInEx/plugins/<あなたの Mod>/assets/textures/<テクスチャ名>.png
```

テクスチャの名前は、Assets タブに出るものです。起動時にライブラリがこのファイルを全部読み込み（Direct3D 12 でテクスチャのアップロードが安全なのはこの時点です）、シーンが読み込まれるたびに、元のテクスチャを使っていたマテリアルのプロパティとスプライトすべてに入れます。スプライトは rect、pivot、pixels-per-unit を引き継ぎます。PNG は元と同じサイズにしてください。違うサイズなら、rect は画像に合わせて拡大縮小されます。`AssetReplacements.ApplyNow()` は、その後にゲームが作ったマテリアルやスプライトにも同じことをします。

2 つの Mod が同じテクスチャを差し替えたときは、フォルダ名の並びで後ろの Mod が勝ち、両方の名前が log と Assets タブに出ます。黙って上書きすることはありません。

まだないもの：メッシュ、シェーダー、名前以外の条件で対象を選ぶ `replace.json`。ボーン付きのメッシュ（キャラクター）は当面対象外です。

### ゲームを動かしたままのリロード

Assets タブの **Reload files** は、差し替えの PNG をすべて読み直し、中身が変わったものを入れ替えて当て直します。**Apply replacements** は、すでに読み込んであるテクスチャにマテリアルとスプライトを向け直すだけです。ライブラリの設定で `[Reload] WatchFiles = true` にすると、PNG がディスク上で変わったとき、最後の書き込みから 0.5 秒後に自動で読み直します（Direct3D 12 では動きません）。

リロードはゲームを動かしたままテクスチャをアップロードするので、Direct3D 12 ではゲームが落ちることがあります（Unity UUM-140564）。ネイティブのクラッシュは捕まえられないため、ライブラリはアップロードの直前に印のファイル（`BepInEx/config/<Assets の GUID>.reload-in-progress`）を書き、終わったら消します。次の起動で印が残っていれば、前回のリロードでゲームが落ちたということです。log と Mods 画面にそう出て、`[Reload] AllowReload` は自分で戻すまでオフになり、Direct3D 12 で 2 回続いたらボタンはオフのままになります。起動オプションに `-force-d3d11` を付けて作業すれば、この心配はなくなります。

ライブラリが検知できる失敗は、ファイルごとに扱い、ほかのファイルを止めません。画像でない PNG や、描画ソフトが保存中のファイル（3 回やり直します）は、前のテクスチャのままにして、**Show replacements** に理由つきで並びます。

## 取り出すと取り込む

予定です。オブジェクトエクスプローラーに並ぶもののうち、平文の形にできる種類は、すべてファイルに書き出し、手を加え、Mod から取り込めるようにします。Mod のリリースに何を入れてよいかは [CONTENT_POLICY.ja.md](CONTENT_POLICY.ja.md) に従います。手で作ったものか手を加えたものはよく、ゲームのデータそのままは入れません。

| 種類 | 書き出し | 取り込み（Mod が同梱） |
|---|---|---|
| テクスチャ、スプライト | PNG。GPU から読み戻すので、ゲームの圧縮テクスチャでも取れる | PNG。今と同じ（`assets/textures/`） |
| メッシュ（ボーンなし） | OBJ | OBJ。同じ名前のメッシュを差し替える（`assets/meshes/`） |
| マテリアル | JSON。シェーダーのプロパティの値とキーワード | 変える値だけを書いた JSON（`assets/materials/`） |
| シェーダー | JSON。プロパティとキーワード（コンパイル済みのシェーダーは書き出さない） | なし |
| AudioClip | WAV。サンプルを読めるクリップだけ（ストリーミングのものは不可） | WAV。同じ名前のクリップを差し替える（`assets/audio/`） |
| ScriptableObject などシリアライズできるもの | シリアライズされるフィールドの JSON（`JsonUtility`） | 変えるフィールドだけを書いた JSON。元のオブジェクトに上書きする（`assets/data/`） |
| テキストと会話 | Drag'n Wash Localization の書き出し | その翻訳パック |

- **置き場所。** 書き出しは `BepInEx/exports/<ゲームのビルド>/<種類>/` に置き、ファイルが何で、手元にとどめるものだと書いた `NOTICE.txt` を添えます。取り込みは `BepInEx/plugins/<自分の Mod>/assets/<種類>/<名前>.<拡張子>` から読みます。
- **どこから書き出すか。** Inspector のオブジェクトエクスプローラー（`experimental/object-explorer` ブランチで設計中）の各オブジェクトと、Assets タブの各行に **Export** ボタンを付けます。コンソールでは `export <種類> <名前>`。開発者ツールのときだけです。
- **取り込みを当てるとき。** 起動時に読み（Direct3D 12 でアップロードが安全なときです）、テクスチャと同じく、シーンを読み込むたびと **Apply replacements** のときに当てます。データの取り込みは、ファイルに書いたフィールドだけを変えます。
- **ぶつかったとき。** 2 つの Mod が同じものを取り込むときは、テクスチャと同じく、フォルダ名の並びで後ろの Mod が勝ち、両方の名前が log と Assets タブに出ます。
- **手を加えていない書き出し。** 書き出しは決定的なので、中身を含めずにハッシュを公開できます。`ci/asset-fingerprints.json` に載せ、`pack.ps1` と CI は、手を加えていない書き出しを含む Mod の zip を拒否します。
- **対象外。** アニメーションクリップ（ゲームのビルドにはカーブを読む API がない）、フォント、コンパイル済みのシェーダー、ボーン付きのメッシュ（キャラクター）。

## Mod 作者向け

```csharp
// 差し替えに呼ぶものはありません。ファイルを同梱するだけです。何があるかを見るには：
foreach (TextureInfo t in AssetCatalog.Textures())
    if (t.MaterialUsers > 0) Log($"{t.Name} {t.Width}x{t.Height} {t.Format}");

// ゲームのテクスチャから自分でマテリアルやスプライトを作ったあとに：
AssetReplacements.ApplyNow();
```
